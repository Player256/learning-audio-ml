1. The Problem CTC Solves

Why can't we just use normal supervised learning?

Analogy: Imagine you have an audio recording of someone saying "cat" that is 100 time-steps long. You know the answer is "cat" (3 characters), but you do NOT know which of those 100 time-steps correspond to 'c', 'a', or 't'. That's the alignment problem.

In normal classification, each input has exactly one label. But in speech recognition:

  • The input (audio) has hundreds of time-steps
  • The output (text) has far fewer characters
  • We don't know which audio frames go with which character
  • Different speakers say the same word at different speeds

The key insight: CTC says "I don't care about the exact alignment. I'll consider ALL possible alignments and sum up their probabilities." This is what makes it so powerful.

2. The Blank Token (ε)

CTC's secret weapon for handling silence and repeated characters

Analogy: Think of the blank token like a "silence" or "nothing happening" marker. Between saying 'c' and 'a', your mouth is transitioning — that's a blank. During a pause — that's a blank too.

Why do we need blanks?

Problem 1: Silence

Not every audio frame contains a character. Some frames are silence, transition sounds, or noise. The blank gives the network a way to say "nothing useful here."

Problem 2: Repeated chars

How do you tell "helo" from "hello"? The word "hello" has two L's in a row. Without blanks, consecutive L's would merge into one. Blanks separate them.

3. The Collapsing Rules

How CTC converts a long alignment back into the short output

CTC's collapsing is a two-step process applied to an alignment (same length as input):

  1. Merge consecutive identical characters → aaa → a
  2. Remove all blank (ε) tokens → ε disappears

4. Why Sum Over All Paths?

The core idea behind CTC loss

Analogy: Imagine asking "what's the probability of getting from home to work?" There are many routes. You don't pick just one — you add up the probability of ALL routes. That total is your answer. CTC does the same with alignments.

The neural network outputs a probability distribution over characters at each time-step. For a given target word, CTC computes:

P("cat" | audio) = Σ P(alignment) for every alignment that collapses to "cat"

Target: "hi" with T=4 input time-steps. Each alignment must be length T and collapse to "hi".

Even for the tiny word "hi" with a few time-steps, there are many valid alignments. For real speech (hundreds of time-steps, dozens of characters), the number is astronomically large — like 1040. We can't enumerate them. We need a smarter way...

5. Dynamic Programming to the Rescue

Computing the sum efficiently without listing every path

Analogy: Imagine counting all paths through a city grid. Instead of walking every path, you stand at each intersection and ask "how many ways could I have gotten here?" That's dynamic programming — you reuse answers from previous intersections. CTC does this with probabilities.

The Expanded Sequence (Z)

First, we create an expanded version of the target by inserting blanks:

"cat" → [ε, c, ε, a, ε, t, ε]

This Z sequence has length 2U+1 (where U = number of output chars). It represents all the "states" an alignment can be in at any time-step.

The Alpha (α) Values

α(s, t) = "total probability of all partial alignments that have produced the first s tokens of Z after t input time-steps."

Transition Rules

At each time-step, from state s, you can:

Case 1: Can't skip

When current token is ε (blank), OR current token equals the token 2 positions back (e.g., both are 'a'):

→ Can come from same position (s) or one back (s-1)

α(s,t) = [α(s,t-1) + α(s-1,t-1)] × P(token_s at time t)

Case 2: Can skip the blank

When current token is a character AND is different from 2 positions back:

→ Can also come from two back (s-2), skipping the blank between different characters

α(s,t) = [α(s-2,t-1) + α(s-1,t-1) + α(s,t-1)] × P(token_s at time t)
Why can't we skip for repeated chars? If the target has "ll" (like in "hello"), we MUST pass through the blank between them — otherwise the two L's would merge into one L when we collapse!

7. Decoding: Getting the Output

Training uses the loss, but how do we get actual predictions?

Method 1: Best Path Decoding (Greedy)

At each time-step, pick the most likely character, then collapse.

Each column shows the network's probability distribution at one time-step. The greedy pick (highest probability) is highlighted. Watch what happens when we collapse.

Method 2: Beam Search (Smarter)

Instead of being greedy, keep track of the top-K most promising prefixes (not alignments!).

Key trick: Normal beam search tracks raw alignments like "ccε a". CTC beam search tracks the collapsed output like "ca" — and combines probabilities from all alignments that produce that same output. This is much more efficient.

8. CTC Properties & Limitations

What CTC assumes, and what that means in practice

✓ Strengths

  • No alignment needed — just pairs of (input, output)
  • Differentiable — plug into any neural network and train with backprop
  • Flexible input lengths — handles variable-length sequences naturally
  • Swappable LM — can plug in different language models at decoding time

✗ Limitations

  • Conditional independence — assumes outputs are independent given input (no "language model" built in)
  • Monotonic only — can't reorder (rules out translation)
  • Many-to-one — each output char maps to one "position" (can't do multi-char units like "th")
  • Output ≤ Input — output sequence can't be longer than input

CTC can't tell the difference between "triple A" (aaa) and "the letter A" (a) from context alone, because it assumes each character's probability is independent. Toggle to see the difference:

With CTC, after predicting the first 'a', the model doesn't "know" whether more 'a's should follow. The probability of the next character doesn't change based on what was already output. A separate language model is needed to handle this.

Summary: The CTC Pipeline

1
Input → Audio waveform split into T time-steps, fed through a neural network
2
Network output → At each time-step, a probability distribution over all characters + blank
3
CTC Loss (training) → Use forward algorithm on the trellis to sum probabilities of ALL valid alignments. Loss = -log of this sum.
4
Backprop → Gradients flow through the DP computation to update the network
5
Decoding (inference) → Use beam search to find the most likely output sequence
The one-sentence summary: CTC lets you train a neural network to map variable-length inputs to variable-length outputs by defining the loss as the negative log of the total probability of ALL alignments between input and output, computed efficiently with dynamic programming.
Based on Sequence Modeling With CTC by Awni Hannun (Distill, 2017)
